September 12 follow-up: AX output and browser readiness

Adaptive AX output now chooses a full current tree when a diff would be larger, and removes text values consisting only of embedded-object placeholders. Replaying the same recorded observations reduced output from 2,895,858 to 2,124,643 characters (26.6%). This is an offline output-size comparison, not a measured model-token or latency improvement. Readable text and element indices are preserved.

Firefox exposes EditableText interfaces on many non-editable nodes. Metadata now also requires the EDITABLE state. The first implementation inadvertently changed automatic click routing: a Google suggestion used AT-SPI activation instead of the previous pointer path and brought Zen to the foreground. The monitor stopped the task, and the controller restored the user's foreground. This was a real refocus, distinct from the earlier address-reuse false alarm. The failed attempt and reconstructed, hash-verified source remain in astra-ax-output.

The correction preserves the original interface-based pointer routing separately from accurate editability metadata. A regression test exercises the actual dispatch decision. The recovery Google run completed in 65.0 seconds without detected refocus, but used keyboard navigation only; it does not validate a live suggestion click. Explicit AT-SPI activation remains capable of focusing the browser, and the popup guard does not prevent all root-window activations.

Browser readiness remains unresolved. Three ordinary key sequences and three experimental main-surface sequences all failed to reach the requested Example URL. Adding 1.2-second delays did not solve it. Neither experiment caused a detected refocus. The main-surface routing experiment was removed. Per-key synthetic focus transitions and background frame delivery need further diagnosis; neither is an established cause. A separate suggestion-click probe stopped without clicking because the expected suggestion was absent.

Timing metadata already disappears from the sampled model-facing Codex recordings: zero of 21 tool outputs across three threads contained the timing fields, although wire recordings retain them. Removing it therefore has no demonstrated model-context saving. Detailed timings remain enabled.

Checks passed: five unified MCP tests; AX state, placeholder filtering and pointer-routing regressions; fast adapter, semantic AT-SPI click, strict resolver and geometry checks. The eight fixture tasks in astra-ax-output passed before the Google refocus stopped that phase. Subsequent targeted browser and Calc results are recorded separately below and do not replace the earlier 24-task comparison.

Corrected-runtime supplemental runs: Google 65.0s, Find 85.9s, Back/Forward 96.3s, Tabs 105.3s and Calc table 78.8s. All five fresh Astra instances exited normally with no recorded refocus. Independent review confirms all five outcomes, including all 12 Calc cells in AX and a screenshot. Calc’s indexed A1 click used pointer dispatch, while its import confirmation used AT-SPI; indexed browser suggestion routing was not exercised in these recovery runs (keyboard navigation and coordinate-pointer clicks were used). These single runs do not establish an end-to-end speedup. Cleanup closed only the owned fixture and private Calc processes, disabled the temporary rule, and left t3-code-alpha foreground without detected refocus.

Earlier fixed comparison and screenshot optimization

The latest fixed comparison uses 24 tasks, each in a fresh Codex CLI instance with gpt-6-astra and high reasoning. It combines astra-fast tasks 01–22 and astra-fast-completion tasks 23–24. Runtime sources stayed unchanged across those tasks. The monitor was corrected between the two parts after a confirmed false alarm.

Compared with the preceding astra-optimized run, supported outcomes improved from 20/24 to 23/24. Total task time fell from 37m26s to 28m43s, 23.3% less. Tool time fell from 1213.0s to 675.6s, 44.3% less. The 20 tasks with completion evidence in both phases took 1704.1s before and 1312.6s after, 23.0% less. No valid task hit the 180-second limit. These are single attempts, with dependent Calc tasks and retained browser tabs, not statistical confidence estimates.

The eight fixture tasks all passed. Their total time fell from 342.9s to 218.3s; tool time fell from 88.2s to 34.8s. Table entry, formulas, sum, sorting, committed decimal formatting and the correct chart all passed independent review. Save reached the correct path but was blocked by a stale lock from the earlier benchmark profile. That failure remains in the fixed comparison.

After confirming the old Calc process was absent, the controller archived its stale lock. One supplemental agent stopped at the existing warning without retrying. A second agent received the cleanup context, selected Retry Saving and completed the save in 81.6s. Independent ODS inspection confirms exact formulas, sorted data, total 28, bold headers, inherited two-decimal formatting and one column-chart series using D2:D4 with categories A2:A4. This recovery is separate from the 23/24 result. The basic XML checker does not resolve column defaults; ods-review.json supplies the complete formatting evidence.

Implemented changes:
• Control commands run through a resident Python interpreter and direct Hyprland IPC. Validation and native input guards remain. Control work under keyboard dispatch fell from 118.8s to 4.5s across the fixed attempts.
• Mutations return acknowledgements without automatic AX scans or the old 350 ms wait. AX-index actions refresh and strictly rematch the selected element before dispatch. Agents explicitly observe when they need new state.
• Screenshot-only observations skip AX and global-menu scans. Menu discovery is cached briefly; menu item state remains fresh. Duplicate AX output hints were removed.
• Dialog protection retains its 400 ms interval and native early-map guard. A compositor event observer replaces repeated control polling, with fallback to the original guarded path if the observer fails.
• Calc grid coordinates use agreement between two scrollbar wrappers to measure the GTK/VCL translation, including a measured zero offset. Repeated C5/D2 validation and live benchmark A1/C5 clicks passed without coordinate recovery.

Remaining costs in the fixed run: AT-SPI scans consumed 302.2s; screenshot command processing 181.3s; global-menu collection 76.8s; session completion self-time 50.3s. These categories have different scopes; the report exposes nested spans. Outside-tool time was 1047.9s and includes model generation, startup, scheduling and transport. It is not pure reasoning time. The agents used 141 JS cells and received 41 images, versus 117 and 24 previously. Extra browser observation/recovery consumed some of the input savings. Text responses totaled 2.70 million characters and timing metadata 1.94 million; these are serialized sizes, not confirmed model token costs.

Five-repeat fixture probes after the fixed run measured medians of 0.323s for AX, 1.337s for setValue and 4.141s for screenshots. The first key probe was blocked by an active seat grab. After closing the verified saved private Calc instance, five key calls passed with a 0.417s median. The grab owner was not identified. Previous medians were 1.562s, 5.973s, 5.787s and 5.847s respectively. These are warmed samples, separate from full model runs.

A further screenshot optimization was implemented after the fixed comparison. A synthetic 1920×1080→1280×720 resize took 2.448s in the Python pixel loop and 0.0216s through GdkPixbuf. The native bilinear filter differs slightly in pixels, with mean channel difference 0.161/255 in that test. Dimensions and coordinate mapping are unchanged. RGBA orientation, color and alpha tests passed. Five live screenshot calls then had a 0.241s median. This improvement is not folded into the fixed 24-task timings. The supplemental astra-native-resize phase records fresh Google/Find tasks with the final resizer.

Browser readiness remains unresolved. Several tasks needed another Enter or repeated observations before navigation became visible. A four-sequence comparison of pressKey(Return) against newline typing showed stale/partial updates with both paths and did not establish coordinate routing as the cause. No speculative keyboard-routing change was applied. Next investigations should instrument client event processing and background frame delivery, reduce AX output volume, and measure whether timing metadata reaches model context. A persistent AT-SPI worker would need crash and hang isolation before adoption.

Focus evidence for the earlier fixed 24-task comparison: no confirmed agent-caused refocus occurred in those valid tasks. The original monitor raised one false alarm when an unrelated hyprnav-browser-dev window reused the address of a closed Calc Text Import dialog. Task 23 had made no tool calls. Raw logs and the interrupted attempt remain available. The corrected monitor discards closed/reallocated addresses; a regression test confirms that genuine target activation still stops a run. Temporary initial-focus and activation-suppression rules were part of the tested setup. This evidence is not a universal guarantee for every application or popup.

Regression checks cover strict AX rematching, ambiguity rejection, no dispatch retry, deferred observations, delayed dialogs, observer fallback, grid geometry, address reuse and native RGBA resize. The four unified MCP tests passed. All 18 existing backend regression scripts had passed before the fixed fast phase. Separate recordings preserve every tool call, returned observation, screenshot, failure and available nested timing.

The final native-resize Google and Find tasks completed in 52.9s and 63.9s, versus 64.7s and 83.9s in the fixed fast phase. Both use fresh GPT-6 Astra instances with unchanged high reasoning. These two supplemental attempts do not replace the full comparison. Final cleanup closed only benchmark-owned processes and disabled the temporary named rule, with no detected refocus. User Zen and the unrelated Hyprnav browser remain open.
